# UI（使用者介面）設計規範

最後更新：2026 年 8 月 8 日

目前狀態：裁帶基準已整理成正式共用版面骨架；裁帶頁保留原功能並改用共用骨架。其他舊功能頁目前只完成共用訊息、表單及基礎樣式整理，尚未逐頁改成裁帶版面。裁帶共用化的自主檢查已通過，仍需使用者登入驗收，不因程式檢查通過提前標記為使用者已驗收。

## 一、文件定位與使用方式

- 本文件是製程成本管理系統的正式 UI（使用者介面）規範，統一桌機版文字、色彩、字型、間距、排版、按鈕、表單、表格、提示、視窗、匯入匯出及驗收方式。
- 後續新增功能必須遵守本文件；整理既有功能時，只在當次核准範圍內逐頁套用，不因本文件全面重做所有舊畫面。
- 本文件與 `AGENTS.md（代理助手工作規則）`及 `系統架構規劃.md（全系統架構規格）`共同使用。
- 安全、權限、資料架構及使用者當次確認的優先順序高於純介面規則；需要改變正式架構時，必須先取得使用者明確同意。
- 現階段只設計及驗收桌機介面。手機與平板不在目前範圍內，不得為了小畫面犧牲桌機操作效率。
- 圖片與生成預覽只用來討論排版、密度、色彩及操作層級，不是功能需求文件。
- 圖片中出現但現有系統、正式文件或使用者需求未定義的功能，不得自行加入。
- 實際功能、欄位、流程及權限以現有程式、正式文件及使用者當次確認為準。

### 1.1 規範優先基準

介面判斷依下列順序進行：

1. 使用者最新確認的實際畫面與操作需求。
2. 已驗收的裁帶功能頁實際做法。
3. 本文件的正式共用規則。
4. `UI設計規範與參照/UI模板參考/裁帶統計_採用模板.png（裁帶統計參考圖片）`的色調、密度及分區關係。
5. 其他討論圖片與生成預覽。

- 參考圖片不要求逐像素複製；實際頁面必須依真實資料及現有功能調整。
- 若實際驗收結果與舊圖片不同，應先更新本文件，不得讓舊圖片凌駕已確認的真實頁面。

## 二、目前採用的介面基準

### 2.1 視覺方向

- 預設主題使用深藍側邊導覽、白色頂部列、淺灰頁面背景、白色內容表面、淺藍整合操作區及藍色主要操作。
- 整體風格為「有活力但嚴謹」，保持中等資料密度，適合工廠桌機長時間操作。
- 以細邊框、淡色背景、間距及分隔線建立層級；一般資料頁不使用重陰影、多種漸層或大量浮動卡片。
- 主要視覺焦點依序為目前工作、主要操作及主要資料；裝飾圖示、摘要數字與次要狀態不得同時搶焦點。

### 2.2 後續頁面必守摘要

- 功能名稱放在共用頂部列左側，與右側帳號及登出同列；內容區不重複放大型頁面抬頭。
- 側邊導覽可以收合；控制放在標誌區右上角並完全位於導覽框內，不得突出到內容區。
- 同一功能的工作分頁使用相連式平面分頁，不做成浮動卡片。
- 工具狀態、目前檔案或工作對象及主要操作，優先整合成一條橫向操作區。
- 操作按鈕使用全系統一致尺寸；空間足夠時直接顯示，不得預先收進「其他操作」。
- 同一操作列最多強調一個主要操作；需要先匯入、選擇或完成檢查的主要操作，在前置資料尚未就緒時與其他操作一致使用白底，前置資料就緒後才切換為主要深藍色。
- 檔案入口使用精簡藍色虛線框；整個框可點擊或拖入，同時支援整個應用程式可視內容區拖入。
- 一般頁面使用主頁面垂直捲動，不建立需要先捲到底才能操作的內層捲動框。
- 一般內容不得造成水平捲動；只有確實過寬的主要資料可以保留唯一一條頁面層級水平捲軸。
- 不把每個狀態、摘要、篩選及操作分別做成卡片；一般頁面以一個主要工作框體為原則。
- 成功摘要已足以表達結果時，不再重複顯示整條綠色成功通知。
- 使用說明按需開啟，不在正常工作畫面永久放置大段黃色或綠色文字。
- 主題、字型、文字、排版及功能程式必須分開管理，任何一項替換不得牽動其他項目。

## 三、介面文字規則

### 3.1 語言與結構

- 系統介面只使用越文與中文，不使用英文作為主要顯示語言。
- 越文為主，中文為輔；新增或修改的功能名稱、按鈕、欄位、表頭、提示、狀態及錯誤必須同時提供兩種語言。
- 固定寬度元件預設採雙行：越文在上，中文在下。
- 越文與中文必須是兩個獨立文字區塊，不得合併成單一字串後交由瀏覽器任意換行。
- 只有在 1280 × 720 像素確認兩種語言都能完整顯示時，才可使用「越文 / 中文」單行格式。
- 表格表頭、功能分頁、按鈕、狀態列、提示框及彈出視窗標題優先使用雙行格式。
- 載入、確認、儲存、匯入、匯出、成功、失敗及取消等動態狀態，同樣必須使用雙語結構。

### 3.2 短文字與長文字

- 按鈕、狀態、欄位名稱、表頭及小型提示使用越文在上、中文在下。
- 大量說明、公告及操作步驟分成兩個完整區塊：先完整越文，再完整中文；不得逐句交錯。
- 同一欄位有多行內容時，必須先完整顯示該欄位全部越文，再完整顯示全部中文；不得使用「越文、中文、越文、中文」的交錯順序。
- 欄位名稱必須固定可見，不得只放在輸入框提示文字內。
- 輸入框提示文字只用來顯示格式或範例，不得代替欄位名稱。
- 越文在視覺上較主要；中文可稍小或稍淡，但不得低於最小可讀字級。
- 文字更新時必須同步更新越文與中文；缺少其中一種語言視為未完成。

### 3.4 文字內容寫法

- 按鈕優先使用「動作＋對象」，例如「Xác nhận nhập / 確認匯入」，不得使用意思不明的「確定」或「執行」。
- 危險操作直接寫出動作及結果，例如「Xóa vĩnh viễn / 永久刪除」。
- 錯誤訊息依序說明發生什麼事、哪些內容未完成及下一步可以做什麼。
- 成功訊息說明完成的對象，不只顯示「成功」。
- 權限不足、網路失敗、資料不存在、格式錯誤及系統錯誤分開處理。
- 省略符號統一使用「…」。
- 數字、日期、金額、百分比及單位格式全系統一致。
- 所有金額及匯率顯示值必須使用逗號千分位，例如 `100000` 顯示為 `100,000`；計算、比對及儲存仍使用不含逗號的純數值，不得把顯示格式寫入正式資料。
- 金額輸入框取得焦點時可使用純數字方便編輯，完成輸入或離開欄位後必須恢復千分位顯示；格式化不得改變原始數值、四捨五入規則或計算結果。
- 無法避免的英文技術名稱或格式後方加中文說明，例如 `Excel（表格檔）`、`PDF（可攜式文件）`及 `UID（使用者識別碼）`。

## 四、桌機框架與頁面排版

### 4.1 支援尺寸

- 最小驗收：1280 × 720 像素。
- 主要驗收：1366 × 768 像素。
- 寬螢幕補充驗收：1920 × 1080 像素。
- 登入畫面原有的小畫面處理可以保留，但不代表業務功能已支援手機或平板。
- 最小尺寸內，主要按鈕、篩選、摘要及主要資料操作不得被遮住或藏在畫面右側。

### 4.2 共用框架

- 側邊導覽展開寬度維持 220 像素；收合後保留約 44 像素窄列及清楚的展開入口。
- 收合控制固定在標誌區右上角，完全位於深藍導覽框內，不遮住內容。
- 收合與展開不得重載、切換或清除目前功能；狀態只保留於當次登入，登出或切換帳號後回復展開。
- 頂部列高度維持 50 像素。
- 頂部列左側由中央功能清單顯示目前功能的越文及中文名稱；右側保留帳號及登出。
- 各功能頁不得自行寫死共用頂部標題，也不得在內容區重複大型主標題。
- 主內容使用剩餘寬度，所有主要區塊的左右邊界保持對齊。

### 4.3 功能頁順序

功能頁原則上依序呈現：

1. 共用頂部列功能標題。
2. 裁帶式平面功能抬頭列；同組頁面依權限顯示，只有一個頁面時仍顯示一格。功能內已有同規格工作分頁時，以該列作為抬頭，不重複增加外層單格。
3. 工具狀態、目前檔案或工作對象及主要操作的整合操作區。
4. 必要的搜尋、日期及篩選。
5. 能協助立即判斷的精簡摘要列。
6. 表格或主要工作內容。
7. 分頁，以及載入、空資料、錯誤與結果狀態。

- 不需要的區塊直接省略，不保留空白占位。
- 不得只為填滿畫面新增摘要、卡片、說明或操作。

### 4.4 裁帶基準共用骨架

裁帶頁已驗收的排列方式是後續頁面的正式共用骨架，功能頁依實際需要組合下列元件：

| 版面用途 | 正式共用類別 |
|---|---|
| 功能抬頭與平面工作分頁 | `ui-tabs（共用平面分頁）`、`ui-tab（共用分頁按鈕）`、`ui-page-tabs（共用功能抬頭列）` |
| 單一工作面板 | `ui-work-panel（共用工作面板）` |
| 橫向整合操作區 | `ui-operation-panel（共用整合操作區）`、`ui-command-row（共用操作列）` |
| 工具、檔案或工作對象 | `ui-context-grid（共用情境格線）`、`ui-context-item（共用情境項目）`、`ui-file-picker（共用檔案入口）` |
| 固定操作方塊 | `ui-command-actions（共用操作群組）`、`ui-command-action（共用操作方塊）` |
| 分段摘要列 | `ui-summary-row（共用摘要列）`、`ui-summary-item（共用摘要項目）` |
| 主要資料區 | `ui-data-section（共用資料區）`、`ui-section-header（共用區塊標題）`、`ui-table-frame（共用表格框架）` |

- 後續功能頁先套用正式共用類別，再用功能專屬類別連接原有程式；不得複製一套新的功能專屬骨架。
- 每個正式功能頁都必須在主內容最上方保留裁帶式平面抬頭；不得因功能群組只有一頁而省略。
- 功能專屬樣式只保留該功能獨有的狀態、欄寬、資料內容與例外排列；不得重複定義共用分頁、操作列、摘要列或資料區骨架。
- 共用化不得更動原有元件識別、事件、資料讀寫、計算或權限；某頁不需要的區塊可省略，不為了形式一致加入空白內容。
- 共用骨架的結構、尺寸或狀態規則變更時，必須同步回歸所有已套用頁面；單一頁面的必要差異留在該功能專屬樣式。

### 4.5 間距、圓角與邊框

- 全系統以 4 像素為基準單位。
- 元件內小間距使用 4 或 8 像素；同一操作群組使用 8 像素。
- 欄位間距使用 12 像素；主要區塊間距使用 12 至 16 像素。
- 主要內容區四周內距使用 16 像素；大區塊上下最多使用 24 像素。
- 輸入框、一般按鈕、提示框及小標籤使用 8 像素圓角。
- 整合操作區、表格外框及內層面板使用 10 像素圓角。
- 主要內容框與彈出視窗使用 12 像素圓角。
- 一般邊框使用 1 像素；資料功能頁預設不使用陰影。
- 選取狀態使用背景、邊框、底線及文字色共同表示，不只依賴陰影。

### 4.6 扁平工作區與捲動

- 一般資料功能頁原則上只使用一個主要內容框體；確實有兩個不同工作目的時最多使用兩個。
- 超過兩個主要框體時，必須先說明拆分原因與使用動線並取得確認。
- 搜尋與表格屬於同一資料範圍時，篩選列直接接在表格上方，不另建卡片。
- 相關的狀態、檔案、提示及操作整合在同一操作區，以分隔線及留白區分。
- 不得出現卡片內再套多層卡片；內部分區使用標題、留白、淡色背景或細分隔線。
- 功能頁可以上下捲動，但一般頁面不得左右捲動。
- 資料確實過寬時，只允許主要資料形成一條頁面層級水平捲軸。
- 不得再建立需要先捲到底才能左右操作的表格內層捲軸，也不得同時出現內外兩條水平捲軸。
- 長清單、已儲存模板及問題結果使用頁面主垂直捲動，不建立固定高度的內層垂直捲動框。

## 五、色彩、主題與字型隔離

### 5.1 正式語意色

新介面只使用下列正式語意色，不直接使用舊簡寫名稱：

| 用途 | 正式變數 | 預設色值 |
|---|---|---|
| 導覽背景 | `--ui-color-navigation-background（導覽背景色）` | `#1a3a5c` |
| 導覽文字 | `--ui-color-navigation-text（導覽文字色）` | `#ffffff` |
| 主要互動 | `--ui-color-primary（主要互動色）` | `#2563a8` |
| 主要互動停留 | `--ui-color-primary-hover（主要互動停留色）` | `#2d5f8e` |
| 主要互動淡色 | `--ui-color-primary-soft（主要互動淡色背景）` | `#dbeafe` |
| 頁面背景 | `--ui-color-page-background（頁面背景色）` | `#f8fafc` |
| 內容表面 | `--ui-color-surface（內容表面色）` | `#ffffff` |
| 共用邊框 | `--ui-color-border（共用邊框色）` | `#e2e8f0` |
| 主要文字 | `--ui-color-text（主要文字色）` | `#1e293b` |
| 次要文字 | `--ui-color-text-muted（次要文字色）` | `#64748b` |
| 提示文字 | `--ui-color-text-subtle（提示文字色）` | `#94a3b8` |

| 資訊 | `--ui-color-info-*（資訊語意色組）` | 藍色系 |
| 成功 | `--ui-color-success-*（成功語意色組）` | 綠色系 |
| 警告 | `--ui-color-warning-*（警告語意色組）` | 黃棕色系 |
| 錯誤與危險 | `--ui-color-danger-*（錯誤與危險語意色組）` | 紅色系 |

- `--navy（舊深藍主色）`、`--accent（舊主要互動色）`、`--ok（舊成功色）`等舊名稱只保留相容舊頁，不得用於新功能。
- 同一主題不得為單一頁面新增相近但不同的藍、綠、黃或紅色。
- 顏色不得是狀態的唯一辨識方式；成功、警告及錯誤同時使用文字，必要時加圖示。
- 紅色只用於刪除、永久清除、不可回復或確實失敗，不用於一般取消。

### 5.2 主題隔離

- 目前藍白灰是預設主題，不得將實際色值分散寫入各功能頁。
- 排版只負責結構、尺寸與互動狀態；主題只負責顏色、透明度及圖示色。
- 功能元件使用用途命名的語意色，不得依「藍色」或「綠色」判斷功能。
- 每套新主題使用獨立定義，透過中央主題登記與根層 `data-ui-theme（使用者介面主題識別屬性）`切換。
- 新增主題原則上只新增主題定義及中央選項，不修改功能程式、文字或排版。
- 移除非預設主題只移除該定義及選項，不得影響其他主題、排版、資料或功能。
- 主題不存在或載入失敗時，安全回復藍白灰預設主題。

### 5.3 字型與字級

- 一般介面只引用 `--font-sans（無襯線字型變數）`；識別碼與逐字比對內容可使用 `--font-mono（等寬字型變數）`。
- 預設字型順序為 `Segoe UI（視窗介面字型）`、`Noto Sans（思源無襯線字型）`、`Noto Sans TC（繁體中文無襯線字型）`、`Microsoft JhengHei（微軟正黑體）`、`Arial（西文字型）`及系統無襯線字型。
- 新字型只改變字形，不得改變字級、行高、雙語順序、元件尺寸、欄寬、間距或功能。
- 配色與字型分開切換，不建立固定的「配色＋字型」組合。
- 新增或移除字型只處理獨立字型定義及中央選項，不修改各功能頁。
- 字型不存在或載入失敗時，安全回復預設字型順序。
- 可選字型必須完整支援越文、繁體中文、數字與必要符號，並通過三種桌機尺寸驗收。

| 層級 | 越文字級 | 中文字級 | 用途 |
|---|---:|---:|---|
| 頂部功能名稱 | 14 像素 | 10 像素 | 共用頂部列左側 |
| 區塊標題 | 14 像素 | 11 像素 | 主要工作區與表格標題 |
| 按鈕與分頁 | 13 像素 | 10 像素 | 固定寬度操作元件 |
| 一般內文 | 14 像素 | 14 像素 | 說明及一般內容 |
| 欄位標籤 | 12 像素 | 10 像素 | 表單標籤 |
| 表格表頭 | 11 像素 | 10 像素 | 雙行表頭 |
| 表格內容 | 12 像素 | 12 像素 | 資料列 |
| 輔助提示 | 11 像素 | 11 像素 | 次要說明 |

- 一般內文行高使用 1.5；按鈕及緊湊表格使用 1.2 至 1.35。
- 除版本號或極次要資訊外，畫面文字不得小於 10 像素。
- 全域拖曳提示另依第 7.2 節使用較高的最小可讀字級。

## 六、分頁、操作區與按鈕

### 6.1 平面功能分頁

- 每個正式功能頁都必須顯示平面功能抬頭。同一功能群組有多頁時，抬頭列只顯示目前帳號可使用的頁面；只有一個頁面時仍顯示一格。
- 功能本身已有同規格內部工作分頁時，以該分頁列作為功能抬頭，不再重複增加外層單格；裁帶的訂單、模板及歷史列即為正式範例。
- 分頁採相連式平面排列，越文在上、中文在下；一般分頁不放圖示。
- 分頁靠左排列，下方基準線延伸至內容右側，不加入陰影或卡片外框。
- 選取狀態使用主要互動色文字及 3 像素同色底線。
- 同組分頁高度一致，建議 56 至 64 像素；不得因文字長度上下跳動。
- 分頁寬度依名稱決定，不強制平均填滿整列；分頁過多時重新分組，不使用整頁水平捲動。
- 動態產生的功能抬頭與頁面內工作分頁必須共用相同類別及外觀；不得另建大型圓角卡片、陰影、圖示式功能卡或不同的選取背景。

### 6.2 橫向整合操作區

- 整合操作區使用操作背景語意色、1 像素邊框及 10 像素圓角，不使用陰影。
- 依實際需要由左至右放置工具或來源狀態、目前檔案或工作對象及操作按鈕。
- 缺少某類內容時直接省略，不保留空白欄。
- 同一流程以分隔線及 16 像素以上留白區分，不把每個狀態拆成小卡片。
- 狀態、檔名及格式提示保持精簡，不得用少量文字撐出大型高卡片。
- 操作列在 1280 × 720 像素仍須完整顯示主要狀態與操作，不得依賴水平捲動尋找按鈕。
- 長檔名最多顯示兩行並省略結尾；完整內容用滑鼠停留輔助文字或明確查看方式提供。
- 長文字、替換字型或匯入內容不得撐高整條操作列。
- 固定 86 像素高度的共用操作列只供單排內容使用；兩排以上的輸入表單必須改用功能專屬的自動增高排列，父框必須完整承接所有欄位、輔助資料及欄位錯誤，不得讓內容溢出到提示或資料區。
- 多排表單右側仍只保留標準尺寸的主要操作按鈕，按鈕貼齊最後一排操作位置；上方剩餘區域沿用操作背景，不得形成白色空塔或把按鈕拉成整欄高度。
- 操作按鈕必須跟隨父框架的實際高度、背景、邊界及圓角，不建立自己的浮動層。
- 最右側按鈕承接外框右上及右下圓角，不得出現方角突出或按鈕超出底框。

### 6.3 按鈕層級與尺寸

| 類型 | 外觀 | 用途 |
|---|---|---|
| 主要操作 | 主要互動色背景與高對比文字 | 儲存、確認、匯出或開始主要工作 |
| 次要操作 | 內容表面背景、主要文字與共用邊框 | 取消、返回、重新顯示 |
| 危險操作 | 內容表面背景、危險文字與邊框 | 刪除、清除及不可回復操作 |
| 圖示操作 | 固定方形並有雙語輔助名稱 | 關閉、收合及展開 |

- 單行按鈕高度至少 36 像素；固定寬度雙語按鈕高度至少 48 像素。
- 整合操作區直向按鈕標準尺寸為 108 × 86 像素；1280 像素寬度可全組一致縮為 100 像素寬。
- 同一操作區及不同頁面的同類按鈕保持相同寬高，不因數量較少平均拉寬。
- 按鈕結構為圖示在上、越文在中、中文在下，整個區域都可點擊。
- 同一操作群組最多只使用一個實心主要操作；其餘使用次要樣式。
- 刪除與清除固定放在直接操作最右側或「其他操作」最後一組。
- 可用主要操作使用相同的深藍主要互動色。
- 需要前置資料的主要操作，尚未匯入、選擇或完成檢查時使用白底、共用邊框及次要文字色；前置資料就緒後才使用深藍底與高對比文字。一般工作執行中的暫時停用狀態仍須清楚，不得與尚未就緒狀態混淆。
- `hover（滑鼠停留）`、`focus（鍵盤焦點）`、`disabled（停用）`及載入狀態必須清楚。
- 儲存、匯入、匯出及刪除開始後，觸發入口必須暫時停用，避免重複執行。

### 6.4 「其他操作」使用條件

- 「其他操作」不是固定按鈕，也不是低頻功能的預設位置。
- 先以標準尺寸直接排列所有目前適用操作；只有在實際可視寬度確實放不下時才啟用。
- 不得先把按鈕平均拉寬，再以空間不足為由收納功能。
- 不得把按鈕放到畫面右側，再要求使用者水平捲動尋找。
- 收合側邊導覽後仍放不下時，才保留主要與常用操作，將低頻或輔助操作收進選單。
- 「其他操作」固定在操作群組最右側，顯示越文、中文及向下箭頭，不只顯示三點圖示。
- 危險操作以分隔線及危險文字分開，固定在最後。
- 選單展開後不得超出桌機可視範圍；點擊外部、按 `Esc（退出鍵）`或選擇項目後收回。

## 七、檔案匯入與匯出

### 7.1 統一檔案入口

- 檔案入口整合於操作區，使用尺寸一致的藍色虛線框。
- 整個虛線框可點擊選擇檔案，也可直接拖入；不再重複放置另一個「選擇檔案」功能按鈕。
- 尚未選擇時顯示接受格式及點擊／拖入提示；選擇後在同一位置顯示檔名及更換提示。
- 虛線框是精簡操作分區，不得做成占用大面積內容區的獨立投入卡。
- 選檔前後框體高度保持不變，長檔名最多兩行。
- 訂單與模板等不同業務入口使用相同互動形式，但由目前功能分頁決定實際匯入目標。

### 7.2 全域拖曳匯入

- 支援匯入的頁面同時允許將檔案拖入整個應用程式可視內容區，不要求對準虛線框。
- 即使應用程式視窗縮小，只要游標進入網頁可視內容區，仍可接收檔案。
- 使用者實際拖入時，顯示覆蓋可視內容區的淡藍半透明玻璃提示、虛線邊框、匯入圖示及雙語目標。
- 覆蓋層依視窗與主內容相交的真正可視範圍置中，不以整個長頁面高度計算中央位置。
- 覆蓋層越文不得小於 18 像素，中文不得小於 15 像素。
- 可視範圍不足以容納最小可讀文字時，改為只顯示置中的小型匯入圖示，並保留隱藏的雙語輔助名稱。
- 視窗恢復足夠空間後，自動恢復圖示及雙語文字。
- 離開或放開檔案後立即移除覆蓋層，不改變原版面高度。
- 歷史或查詢等不可匯入分頁不得接收正式匯入，必須提示先切換到正確分頁。
- 放開檔案只代表選取及開始檢查，不得立即寫入正式資料。
- 系統必須阻止瀏覽器直接開啟檔案或取代目前頁面。
- 離開功能、切換到不可匯入分頁或登出時，解除接收狀態與相關事件。

### 7.3 檢查、結果與匯出

- 匯入流程依序為選擇檔案、格式檢查、錯誤明細、資料預覽、影響摘要、使用者確認、正式處理及結果。
- 錯誤必須指出工作表、列、欄、識別碼及原因，不只顯示「格式錯誤」。
- 確認前顯示新增、更新、忽略及錯誤筆數。
- 模板解析出的儲存格位置、反推數量及其他技術資料若是計算必要內容，保留於程式內部，不在一般畫面逐筆展示。
- 全部通過時只顯示摘要數字，不顯示完整正常資料清單，也不重複顯示綠色成功通知。
- 缺少模板與錯誤資料顯示必要問題清單，直接說明款號、原因及可執行處理方式。
- 匯出按鈕名稱必須符合實際動作；點擊後直接進入匯出流程時，不得使用「預覽」誤導使用者。
- 匯出開始前先顯示系統儲存位置選擇視窗；取消時停止產生與寫入。
- 瀏覽器不支援位置選擇時，以雙語明確提示並停止，不偷偷改用預設下載位置。
- 儲存失敗時保留既有檔案，不用未完成內容覆蓋。

## 八、卡片、摘要、表單與表格

### 8.1 內容框與摘要

- 主要內容框使用內容表面色、1 像素邊框、12 像素圓角及 16 像素內距。
- 只有需要形成完整工作區時才使用主要內容框，不為每個小標題增加卡片。
- 摘要必須協助使用者立即判斷或執行工作才顯示。
- 多個小型摘要使用一條無陰影、無獨立卡片的分段摘要列。
- 每段只顯示一個指標，使用越文、中文、數值及必要的狀態點；各段以細線分隔。
- 只有單一指標確實需要特別強調且無法放入操作區或表格時，才使用獨立摘要卡。

### 8.2 表單與篩選

- 輸入框與選擇框高度統一為 36 像素，圓角 8 像素。
- 欄位標籤在輸入框上方，越文在上、中文在下。
- 一般表單優先使用兩欄或三欄；短代碼、日期、數量及狀態使用較窄欄位。
- 驗證錯誤放在對應欄位下方，儲存失敗時保留已輸入內容。
- 唯讀與停用欄位必須有不同外觀，且保持可閱讀。
- 以直接輸入為主、沒有逐級增減操作需求的數字設定欄位不顯示瀏覽器原生上下調整箭頭；只有業務流程明確需要逐級調整時才保留。
- 搜尋、日期及狀態篩選放在表格上方並優先同列對齊。
- 篩選生效時清楚顯示目前條件，並提供清除方式。
- 搜尋結果、摘要、表格及匯出必須使用相同條件。

### 8.3 表格與空資料

- 表頭固定雙行：越文在上、中文在下，且是兩個獨立文字區塊。
- 表格使用操作背景語意色表頭、白色資料列、1 像素邊框及 10 像素圓角，不使用陰影。
- 一般資料列高度建議 40 至 44 像素；同一表格保持一致。
- 名稱與說明靠左；數量、金額、百分比及秒數靠右；狀態、圖示及操作置中。
- 操作欄放在最右側，按鈕過多時使用明確次層操作，不塞滿小按鈕。
- 大型表格使用分頁，並顯示目前頁、總頁數或資料範圍。
- 空資料使用統一圖示、越文標題、中文標題及可執行下一步，不只留下空白。
- 載入中顯示表格內載入狀態，不先閃現「尚無資料」。
- 原因與處理方式等雙語長文字表格，兩個主要文字欄依內容約使用 60%／40%寬度；另有識別欄時，先保留必要識別寬度，再於剩餘空間維持相同比例。
- 越文與中文在各自文字區塊內正常換行，資料列與外框隨最高內容自動增高；不得使用禁止換行、縮小到難以閱讀的字級或建立內層水平與垂直捲軸。
- 工作表名稱、資料列及其他位置資訊與原因內容分開成行，但在原因欄內使用相同字級、顏色與字重，不以不同外觀區分；原因與處理文字保留完整內容，不因版面不足自行省略或改短。

## 九、提示、視窗與共用互動

### 9.1 訊息語意

- 資訊使用資訊語意色；成功使用成功語意色；警告使用警告語意色；錯誤使用危險語意色。
- 每則訊息同時包含越文與中文；固定寬度時上下排列。
- 頁面訊息放在相關工作區附近，欄位錯誤放在欄位下方，不全部堆到頁面最上方。
- 正常下一步不用黃色警告，例如「尚未選擇檔案」應在檔案區使用低干擾輔助文字。
- 可重試錯誤提供重試操作；不可重試錯誤提供明確處理方式。
- 成功提示不永久占用大量空間；完成摘要已足夠時不重複顯示。

### 9.2 使用說明與彈出視窗

- 一般使用說明由「Hướng dẫn / 使用說明」按鈕按需開啟，不常駐大段文字。
- 長篇說明先顯示完整越文，再顯示完整中文。
- 操作列開啟的使用說明依主內容區水平置中，不貼齊觸發按鈕，也不得超出功能頁框。
- 一般視窗寬度約 500 像素；包含表格或預覽時約 700 像素，特殊尺寸依內容說明原因。
- 視窗最大高度不超過可視高度；內容可以捲動，標題與主要操作保持容易找到。
- 結構固定為標題、內容、必要狀態及操作按鈕。
- 純閱讀且沒有輸入、確認或資料變更的說明，可允許點擊內容區任意位置收回。
- 表單、刪除、匯入預覽及其他互動視窗，點擊內容區不得關閉。
- 一般選單與非強制視窗支援點擊外部及按 `Esc（退出鍵）`收回。
- 共用彈出視窗仍保留明確關閉入口，不只依賴點擊外部。

### 9.3 共用提示、確認與進度

- 新功能不得使用瀏覽器原生提示或確認框處理重要流程，必須接入共用雙語元件。
- 共用提示至少支援資訊、成功、警告及錯誤。
- 清除、刪除、覆蓋及不可回復操作使用共用確認視窗，明確說明影響，不只詢問「確定嗎」。
- 匯入、匯出、同步、批次寫入及其他長時間工作使用同一套共用進度視窗。
- 進度視窗支援已知百分比與無法預估時間兩種狀態，顯示目前工作、完成、失敗或取消結果。
- 只有業務工作確實支援安全取消時才顯示取消；關閉視窗不代表工作已取消。
- 功能程式提供業務結果、雙語內容、進度與取消能力；共用元件只負責顯示、焦點、關閉及操作鎖定。

### 9.4 防止重複操作

- 非同步工作開始後，觸發按鈕及同一工作的其他入口必須鎖定。
- 短暫按鈕冷卻與實際工作執行中分開管理；按鈕恢復不代表相同工作可重複執行。
- 工作成功、失敗或取消後必須統一復原，避免永久鎖定。
- 裁帶啟動 `PDF（可攜式文件）`工具的按鈕冷卻為 1 秒，實際啟動狀態最多檢查 10 秒。
- 工具仍在啟動時再次點擊，只顯示共用雙語「正在啟動」提示，不重複啟動、不開啟儲存位置，也不自動繼續匯出。
- 每個功能接入後驗收連續點擊、工作失敗、畫面關閉及重新進入，確認不會重複執行或留下永久鎖定。

## 十、程式責任與相容原則

### 10.1 正式分層

| 檔案 | 正式責任 | 禁止內容 |
|---|---|---|
| `styles/ui-core.css（共用介面核心樣式）` | 間距、尺寸、圓角、雙語結構、按鈕、分頁、操作區、表格、訊息、視窗及拖曳覆蓋層結構 | 不保存實際主題色值、字型名稱、業務文字或功能判斷 |
| `styles/themes/default.css（預設藍白灰主題）` | 將導覽、主要互動、表面、文字及狀態語意對應到預設色值 | 不包含寬高、間距、字級、排版或功能程式 |
| `styles/fonts/default.css（預設字型設定）` | 定義一般介面及識別碼使用的預設字型 | 不包含顏色、字級、間距、欄寬或頁面排版 |
| `js/ui-text.js（共用雙語文字程式）` | 登記共用操作與狀態文字，建立越文及中文兩個文字節點 | 不讀寫業務資料、權限或使用雙語斜線字串取代結構 |
| `js/ui-runtime.js（共用介面執行控制）` | 登記、套用及記憶主題與字型，失效時回復預設 | 不包含功能頁排版、業務狀態或資料查詢 |
| `js/ui-components.js（共用介面元件程式）` | 建立雙語按鈕、提示、確認視窗、進度、防重複操作及展開元件 | 不代替功能程式決定業務結果、資料寫入或是否允許取消 |
| `js/ui-file-drop.js（全域拖曳匯入程式）` | 管理可視內容區拖曳、匯入目標、格式、數量、覆蓋提示及離開清理 | 不猜測業務用途、解析正式資料或直接寫入 |

### 10.2 實作限制

- 新增介面不得使用新的行內樣式堆疊版面；重複規則建立共用樣式類別。
- 相同元件不得在不同功能各自複製顏色、間距、圓角及狀態樣式。
- 新增全域樣式變數使用語意命名並說明中文用途。
- 共用排版只負責結構，主題只負責顏色，字型設定只負責字型角色。
- 使用者、`Excel（表格檔）`及雲端來源文字以安全文字方式顯示，不直接插入可執行網頁內容。
- 新增元件同時建立一般、滑鼠停留、鍵盤焦點、停用、載入及錯誤狀態。
- 統一外觀不得成為登入時預載全部功能程式與資料的理由；仍須遵守按需載入及快取規則。
- 介面整理不得改變資料路徑、權限判斷、安全規則、計算結果、匯入匯出內容及操作紀錄。

### 10.3 舊頁相容與搬移

- 舊色彩簡寫暫時由共用核心對應到正式語意色，只用來避免舊頁立即失效。
- 相容層不代表舊頁已完成主題、字型或雙語整理。
- 舊頁的寫死色碼、寫死字型、雙語斜線字串、行內樣式、原生提示及專屬進度，於該頁核准改版時逐步搬移。
- 功能專屬文字在該功能範圍內登記，不把所有頁面文字塞進單一大型共用文字表。
- 整理某個功能頁時，只搬移該頁及直接共用元件，不一次批次改寫全系統。
- 訂單、裁帶及同步原本各自管理進度；後續接入同一套共用進度元件，不建立第二套共用系統。
- 共用元件或拖曳匯入故障時，停用對應登記並保留原有檔案選擇等可用操作路徑。

## 十一、逐頁開發與規範調整

### 11.1 開始前

每次新增或整理功能頁前，先完成：

1. 盤點實際存在及已確認需要的功能、欄位、操作與權限。
2. 確認越文及中文功能名稱與所有動態狀態。
3. 確認主要使用者及桌機工作流程。
4. 列出主要、次要與危險操作。
5. 依第 4.3 節安排頁面順序，省略不需要的區塊。
6. 確認載入、空資料、成功、錯誤、權限不足、網路中斷及取消狀態。
7. 確認使用既有共用元件，不自行建立相近版本。
8. 列出預計讀取及修改的檔案、影響範圍、風險、回復方式及驗收方法。
9. 取得使用者明確同意後才修改。

### 11.2 實作與調整原則

- 先使用真實資料完成實際畫面，再調整間距、欄寬、操作位置及必要摘要。
- 每次只修改當次核准的功能頁及直接共用元件。
- 若規範造成操作不順、過密、過鬆或不必要捲動，先說明問題與建議，再由使用者確認是否更新規範。
- 個別頁面可以依實際工作做必要調整，但不得自行放寬雙語順序、操作層級、語意色、桌機尺寸、匯入確認、安全與權限規則。
- 修改共用元件後，必須重新檢查已完成且直接受影響的頁面。
- 不以生成圖片補出不存在的功能，也不因排版需要改動業務結果。

### 11.3 規範變更

- 新功能不得自行建立例外；特殊業務需求先記錄原因、影響元件、替代方案及驗收方式。
- 改變共用色彩、字級、支援尺寸、雙語順序或主要元件，視為全系統介面規則變更，執行前取得使用者同意。
- 規範變更後同步更新本文件日期與相關章節，不得只改程式不改正式規範。
- 真實頁面驗收後形成的新共用做法，應取代過時規則，不繼續並列互相矛盾的版本。

## 十二、工作節點、確認與進度同步

### 12.1 主導界線

- 代理助手負責拆解工作、提出下一節點、指出遺漏與風險、建議驗收方式及維護進度。
- 「由代理助手主導」不代表可以自行擴大範圍或連續開始下一階段。
- 每次讀取、修改、刪除、搬移、共用元件調整及階段轉換，仍須先說明範圍、風險及是否修改檔案。
- 未經使用者確認，不得因前一階段完成就自動開始下一階段。
- 實際影響超出核准檔案、頁面、功能或風險時，立即停止並重新取得同意。

### 12.2 固定流程

1. 提出本節點處理與不處理的範圍。
2. 說明讀取及修改檔案、目的、影響、風險、回復方式與驗收方法。
3. 使用者同意後執行。
4. 完成後由代理助手先做程式、畫面、文字、尺寸與回歸驗收。
5. 回報實際修改、未完成項目、限制及下一個建議節點。
6. 使用者確認結果並明確同意下一階段後，才同步進度及開始下一階段。

### 12.3 進度狀態

| 狀態 | 說明 |
|---|---|
| 未開始 | 尚未提出或進入 |
| 待確認 | 已提出範圍，等待使用者同意 |
| 進行中 | 已取得同意並在核准範圍內執行 |
| 自主驗收中 | 實作完成，正在檢查結果與回歸影響 |
| 待使用者驗收 | 自主驗收通過，等待使用者確認真實畫面 |
| 完成 | 自主驗收通過，且使用者已同意開始下一階段 |
| 暫停 | 使用者要求暫停或需要新的確認 |

- 使用者明確同意下一階段開始時，可同步把前一階段標記完成、下一階段標記進行中，並更新目前節點及最近進度。
- 此同步授權只限進度內容，不包含新增規範、擴大檔案範圍或修改程式。
- 使用者只確認目前結果但未同意下一階段時，維持待驗收或暫停，不自行轉換。

- [ ] 連續點擊不會重複匯入、匯出、同步、儲存或刪除。
